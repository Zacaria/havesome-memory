CHAPTER FIVE / REAL SYSTEMS

A feature does not remove responsibility.
It moves it.

Morrow Works needed more than search: sources that survive change, useful organization, reliable retrieval, explicit scope, inspectable derivations, permission boundaries, deliberate context, and a workable operating model.

Current memory technologies divide that work differently. The useful question is not “Which one has memory?” It is “Which objects does it create, what do those objects mean, and who remains responsible when they are wrong?”

28 / BEFORE THE BRANDS

First ask what each system makes.

Hindsight distinguishes extracted facts, consolidated observations, and curated mental models. Mem0 stores memories with entity links and temporal metadata, then may consolidate them through Dream. OpenViking presents resources, memories, and skills through a hierarchical virtual filesystem. Supermemory separates source documents from evolving extracted memories. Microsoft GraphRAG builds entities, relationships, communities, and generated reports from a corpus.

Those objects are not interchangeable. A graph edge, folder, embedding, or generated summary is a representation—not proof that the source collection is complete, coherent, authorized, or understood.

29 / HINDSIGHT

Separate retaining, recalling, and reflecting.

An agent-memory system centered on extracted facts, multi-strategy retrieval, consolidation, and reasoning over a memory bank.

raw inputretainfacts + entitiesconsolidateobservationsrecall / reflectbudgeted context or synthesis

What the architecture does

Hindsight documents four parallel recall strategies: semantic similarity, keyword search, graph traversal, and temporal search. Their ranked results are fused, reranked, and returned within a caller-controlled token budget. Raw facts can be consolidated into observations; mental models remain a separately curated layer. Observations can retain references and exact supporting quotes, so a derived belief can be inspected against the memories beneath it.

This directly addresses several moments in the story. Keyword retrieval can preserve exact names such as ATLAS-ROOM-FR. Semantic retrieval can bridge different wording. Graph traversal can reach structurally related facts. Temporal retrieval can distinguish “what applied then?” from “what do we know now?” Reflect can synthesize across those results rather than merely returning a list.

Where responsibility remains

Document identity matters. Re-retaining the same document identifier is documented as replacing the previous document content and its extracted facts. If Morrow Works must preserve S02 and S03 as independently inspectable revisions, it must model those revisions explicitly instead of assuming the memory layer will invent the right history.

Entity resolution is also a judgment. Similar names may merge incorrectly; unrelated aliases may remain separate. Visibility tags and banks are retrieval-scoping primitives, but the application must use strict boundaries and enforce authorization. A delete API establishes a deletion mechanism—not proof that every cache, backup, downstream answer, or external copy is gone.

Morrow Works test

Retain the 14-day base rule and scoped 7-day amendment without turning one into an unconditional replacement. Then trace the resulting observation to both passages, correct a deliberately merged Atlas entity, and verify the repaired derived views.

30 / MEM0

Separate extraction from later consolidation.

A managed or self-hosted memory layer centered on distilled memories, entity-aware retrieval, temporal metadata, and explicit memory operations.

conversationextractADD-only memoriesindexvector + entity + timeDreamsupersede / merge / synthesize

What the architecture does

Current Platform documentation describes a write path that looks up related context, distills facts, deduplicates, embeds, links entities, and extracts temporal metadata. At retrieval time, semantic, keyword, entity, and temporal signals contribute to one ranking. The graph boosts memories connected through shared entities; it is not a user-maintained graph of typed business predicates such as “S03 amends S02.”

The ADD-only extraction model preserves old and new facts rather than overwriting history immediately. Dream performs later consolidation. Its documented relations distinguish superseding an outdated contradiction, merging a duplicate into a canonical memory, and synthesizing a higher-order pattern. That vocabulary is useful because “new evidence,” “same fact again,” and “derived pattern” are different events.

Where responsibility remains

Applicability cannot be reduced to “newer wins.” Morrow Works’ 14-day and 7-day rules coexist because they apply to different booking dates. The application must encode scope well enough that consolidation does not mistake a bounded amendment for a universal contradiction. Default reads and current-only reads also differ; callers must request and test the view they actually intend to use.

Mem0 Platform, its self-hosted server, and the OSS in-process library are distinct operating surfaces. Managed benchmark results include proprietary Platform optimizations and should not be presented as guaranteed OSS performance. Accuracy, tokens retrieved, latency, extraction models, and retrieval depth must be compared under equal constraints.

Morrow Works test

Preserve both scoped cancellation rules; inspect ordinary and current-only reads; then seed a false duplicate and verify whether consolidation merges, supersedes, or retains it—and whether the evidence needed to undo that choice remains available.

31 / OPENVIKING

Make the collection browsable as a hierarchy.

An open-source context database that unifies resources, memories, and skills through filesystem-like paths and layered context.

resources + sessionsorganizeviking:// hierarchysummarizeL0 / L1 / L2retrievetraceable descent

What the architecture does

OpenViking gives context stable viking:// locations and separates resources, memories, and skills. Its hierarchy offers progressively deeper representations: compact L0 abstracts for positioning, L1 overviews for navigation and reranking, and L2 source detail loaded on demand. An agent can use deterministic operations such as listing and reading paths as well as semantic search.

For complex tasks, retrieval first analyzes intent, locates promising directories, explores within them, and reranks candidates. The resulting trace records the directories traversed and files positioned. That makes retrieval behavior more inspectable than an opaque list of nearest chunks and gives unfamiliar readers a way to orient before opening every source.

Where responsibility remains

A hierarchy is still an authored or generated model of the collection. An abstract can hide the France-only qualifier. A directory trace can explain where retrieval traveled without proving that a summary is true or that another branch was not missed. The owner must evaluate hierarchy quality, summary drift, update lag, and whether one item needs several facets rather than a single home.

The current documentation distinguishes user-private and shared resource paths, but deployment configuration, policy enforcement, deletion propagation, backup handling, and downstream context use still require end-to-end tests. Open source also means the operator owns infrastructure and model costs. The repository license must be reviewed for the intended deployment and distribution model.

Morrow Works test

Start from a cancellation-policy overview, navigate to S02 and S03, and confirm that progressive summaries preserve the country, product, and booking-date boundaries. Then inspect the retrieval trace for a deliberately misplaced source.

32 / SUPERMEMORY

Keep source documents distinct from extracted memory.

Context infrastructure combining document retrieval, evolving memory relations, profiles, connectors, and scoped containers.

files + chatsindexdocument chunksdreammemory graphretrieveRAG / memories / profile

What the architecture does

Supermemory distinguishes raw documents—the material supplied for document retrieval—from memories extracted to model personal or entity state over time. Document processing extracts text, chunks it, embeds it, and indexes it. A separate “dreaming” phase groups material and forms evolving memories. Retrieval can return document chunks, traverse memories, or assemble profile context from the same scoped pool.

Memory-to-memory relations carry different meanings. Updates marks a newer state, Extends adds compatible detail, and Derives records an inferred pattern. These are not classic hand-authored entity–predicate–entity triples. The distinction is useful for Morrow Works: “the source reports unused rooms” should remain visibly different from “shorter notice probably improves utilization.”

Where responsibility remains

A derived memory is still an inference. It must not silently become source truth. Document content updates trigger reprocessing, while metadata-only changes do not. Document deletion endpoints exist, but the researched material does not establish complete removal from every extracted memory, profile, cache, backup, or previously generated answer. That must be tested, not inferred from the verb delete.

Container tags and scoped API keys provide isolation mechanisms. The application still chooses source authority, decides which relations count as conflict or enrichment, assembles the permitted final prompt, and verifies that revocation is respected at every read path.

Morrow Works test

Keep S07’s observation separate from the inferred utilization claim. Update or delete the source, then inspect document chunks, graph memories, profiles, caches, and final retrieval to see which objects changed and which remained.

33 / MICROSOFT GRAPHRAG

Build structure for corpus-wide questions.

A research-oriented indexing and query framework for extracting graph structure and hierarchical reports from unstructured corpora.

corpusindexentities + relations + claimsclustercommunities + reportsquerylocal / global / DRIFT

What the architecture does

GraphRAG’s standard indexer uses language models to extract entities, relationships, and optionally claims from text units; it detects communities and generates reports at multiple levels. Local Search combines graph material with underlying text chunks for entity-focused questions. Global Search runs a map/reduce process over community reports to answer questions about themes across the collection. DRIFT begins from community information and expands into follow-up questions.

This is a strong match for the exploration part of the story: “What tensions run across our notes?” is different from “What does policy passage S03 say?” A graph and its community reports can expose a possible connection between unused rooms and cancellation policy that ordinary nearest-chunk retrieval may never place together.

Where responsibility remains

Extraction and reports are generated representations, not authoritative records. Prompts, hierarchy level, context builder, model choice, and token budget all affect the result. A discovered theme must still lead back to source text before it is treated as evidence. Indexing can be expensive, and the project explicitly warns users to start small and tune prompts.

GraphRAG is not a ready-made conversational memory provider. Its researched documentation does not establish source version management, current-versus-historical policy semantics, per-user authorization, revocation, forgetting propagation, or a correction workflow. The GitHub project also currently describes itself as largely in maintenance mode and as a research project rather than an officially supported Microsoft offering.

Morrow Works test

Use community reports to surface the possible utilization-policy tension, then require inspection of S06 and S07 before presenting the relationship as fact. Re-index after a scoped correction and compare both local and global answers.

34 / ONE CORPUS, FOUR HARD TESTS

Run the failure cases, not the logos.

01

Scoped change

Can the system preserve both 14 and 7 days, then select by country, product, booking date, and knowledge date?

02

Exploration

Can it suggest the utilization-policy connection while preserving the labels reported, proposed, and not measured?

03

Correction

If two Atlas entities merge or a summary loses a qualifier, can an owner inspect the evidence, correct the object, and refresh downstream views?

04

Control

If access is revoked or S10 must be forgotten, can the team deny retrieval and trace removal through sources, extracted facts, overviews, profiles, and answer caches?

No mechanism passes these tests merely by existing. A filter is not proof of authorization. A source link is not proof that the source is correct. A delete endpoint is not proof of complete erasure. A generated overview is not proof of corpus coverage.

35 / COST AND OPERATING BURDEN

The bill has more than one unit.

Managed providers may meter writes, retrieved context, synthesis calls, file conversion, storage, or background processing. Self-hosted systems replace some subscription costs with model inference, databases, upgrades, observability, recovery, and engineering time. Graph extraction can make initial indexing and reprocessing materially more expensive than plain chunk-and-embed pipelines.

Compare one explicit workload: initial corpus size, monthly additions and corrections, reprocessing after policy changes, background consolidation, reads, returned context, latency targets, storage, backups, incident response, and human review. Open source, self-hosted, free tier, and two similarly priced plans do not describe the same total cost.

Exact prices are intentionally excluded from the main narrative because they change. Recheck each official pricing page against the planned workload before adoption.

END OF HAVESOME MEMORY

Keep the evidence.
Name the derived objects.
Test the seams.

Memory engineering is not the promise that a system will remember everything. It is the work of deciding what should persist, representing it without hiding its limits, finding and supplying the right evidence, and following change, permission, and forgetting through every derived copy.

The right system is the one whose documented responsibilities fit your collection—and whose remaining responsibilities you are prepared to own and test.
